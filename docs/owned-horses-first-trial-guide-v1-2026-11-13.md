# 所有馬管理・初版試用ガイド

作成日：2026-11-13 JST
対象：`puriponyan/dabimas-tool-preview` ／ `main`
対象機能：所有馬管理のみ
文書の状態：初版試用に向けた文案。外部保存・試用開始・完成宣言は未実施。

## 1. この初版の目的

確認済みの機能を使い、仮データで所有馬管理を試用できる区切りを設ける。

初版の完成は、全条件での動作や、データが消失しないことの保証ではない。試用できる範囲、未確認事項、保存状態の確認方法、警告時の停止方法が明確になっていることを完成条件とする。

配合計画・台帳連携・自動同期・実牧場データの移行は、この初版の対象外とする。

## 2. 正式入口と構成

使用するアプリ：iPhoneのSafari

正式入口：

画面の見出し：所有馬管理・端末内保存v1
正式な保存領域：`dabimas-owned-horses-v1`

正式入口は単体HTMLではない。元HTML・既存10本のJS・現行保存JSの計13本に依存する。入口のハッシュ検証や依存ファイルを変更・削除しない。

現行保存JSは `horse-persistence-stop-notice-v1.js`。旧 `horse-persistence-v1.js`、比較用・隔離用・安全性試験用の入口と混同しない。

正式URLはGitHubの記録本文で確認済み。ただし、このガイド作成時に公開配信版一式の独立照合やSafariでの再確認を行ったものではない。

## 3. 試用条件

### 使用するデータ

- 完全な仮データだけを使用する。
- 今回の試用は、確認済みのJSON往復条件に合わせて2件までとする。
- 実際の馬名、実牧場の原文、台帳全文、実馬由来のスクリーンショットを混ぜない。
- 既存の登録馬・未保存入力・保管JSONを試験用に変更しない。

「2件まで」はアプリの容量上限ではなく、今回の試用範囲を限定するための条件である。

### 操作上の制限

- 複数タブで同時に登録・編集しない。
- 旧ページや比較用ページとの自動移行・自動同期を前提にしない。
- JSON復元は、後述の空の復元先の条件を満たす場合だけ行う。
- 条件を満たすために、既存データを削除したり入力を破棄したりしない。
- 試用中に警告が出た場合は、操作を重ねて解消しようとせず停止する。

既存タブを残すことと、複数タブで同時編集することは別である。保護のため残したタブから、追加の登録・変更反映を行わない。

## 4. 初版の完成判定

### 試用前に必要なこと

| 項目 | 完成条件 |
|---|---|
| 正式入口の特定 | 正式URL、画面見出し、保存領域を手順に明記する |
| 対象範囲の明確化 | 仮データ限定、所有馬管理のみとする |
| 保存状態の説明 | 一覧への反映、端末内保存、JSON取得を区別する |
| 復元条件の説明 | 保存データなし・一覧0件・入力途中なしを明記する |
| 停止方法の説明 | 警告時は追加操作を止め、タブとデータを保護する |
| 制限の明示 | 未確認の環境・操作を合格済みと説明しない |
| 記録の保存 | 確定したガイドと現在地を、承認後にGitHubへ保存し、読み戻し確認する |

最後の記録保存は、この文案を作成しただけでは完了しない。保存時は対象と全文を提示し、専用承認を取る。

### 制限を明示して初版の対象外にすること

- 実牧場データの投入・移行。
- 既存データへのJSON追加取り込み・統合・上書き復元。
- 旧v1・混在JSONの取り扱いを今回の標準試用手順へ含めること。
- 3件以上、全項目の手動修正、全種類の入力への対応保証。
- Safariでの全操作経路、終了・再起動後、長期保持の保証。
- 全種類の不正JSON、保存失敗・競合・容量不足などへの動作保証。
- 参考推定のゲーム数値の正しさ。
- 配合計画・台帳連携・自動同期。

過去に限定確認された経路があっても、それを取り消す意味ではない。今回の標準試用範囲へ広げないという区分である。

### 後続開発へ回すこと

- 編集キャンセル・確認画面から戻る操作の未確認条件。
- 保存失敗・競合などの追加検証。
- 公開配信版の独立照合、必要なSafari追加確認。

## 5. 短いiPhone運用手順

以下は運用手順であり、この文書を読んだ時点で実機操作を開始する依頼ではない。実際の案内は1操作ずつ行い、結果を確認してから次へ進む。

### ① Safariで正式入口を開く

既存の入力中・編集中タブはそのまま残す。利用開始時は、正式入口を新しいタブで開き、見出しと保存状態を確認する。

保存状態の確認中は入力を始めない。

保存データが読み戻された場合は、その内容を消して試用の準備をしない。予定していない登録馬や警告が表示された場合は、追加操作を止める。

### ② 仮データを登録・編集する

入力から作成された候補を確認し、必要な手動修正を行ってから登録する。編集時は、対象馬を確認して変更反映する。

原文・自動抽出結果・手動修正後の値を区別する。未対応の文章や注意情報を、意味の推測だけで確定情報へ変えない。

登録・変更反映後は、一覧への反映に加えて、次の保存状態を確認する。

### ③ 端末内保存の状態を確認する

| 表示 | 扱い |
|---|---|
| 「登録済み○件を端末内に保存しました」 | 今回の確定内容について、アプリが端末内保存を確認した表示 |
| 「登録済みの確定内容を端末内に保存しています」 | 保存処理中。完了を待つ |
| 「前回確認した内容と同じため、今回の書き込みは行っていません」 | 新しい書き込みなし。現在の保存領域を再照合した表示ではない |
| 「端末内の保存データから○件を読み戻しました」 | 起動時の読み戻し結果。新しい編集内容の保存成功とは別 |
| 保存失敗・保存停止・保存結果未確認の警告 | 保存完了として扱わず、追加操作を止める |

入力欄が使えること、確認画面まで進んだこと、一覧に表示されたことだけで保存成功と判断しない。

未登録入力・未確定編集・推定結果は、端末内保存の対象外である。

### ④ JSONバックアップの取得を確認する

使用するアプリ：Safariと「ファイル」アプリ等

端末内保存とは別に、登録済みの確定内容をJSONバックアップとして書き出す。

書き出し開始の表示だけでは、iPhoneへの取得完了としない。「ファイル」アプリ等で対象ファイルを取得できたことを確認する。

- 既存の正常なバックアップを上書きしない。
- 取得確認済みのJSONを、異常系試験のために書き換えない。
- ファイル取得の確認と、内容全文の検査・復元成功を区別する。
- JSONを取得しても、未登録入力・未確定編集が保護されたとは扱わない。

### ⑤ 必要な場合だけJSONを復元する

初版の標準試用では、現行v2 JSONを使用する。

復元前に、次のすべてを確認する。

1. 保存状態が「端末内の保存データなし」である。
2. 一覧が0件である。
3. 入力途中・未確定編集がない。
4. 読み込むJSONが、取得確認済みの予定したファイルである。

「保存済み0件を読み戻した状態」と「保存データなし」は別である。一覧0件という理由だけで復元を始めない。

条件を満たさない場合は停止する。削除・初期化・入力破棄で条件を作らない。

ファイル選択後は読み込み確認の件数・馬名を確認し、予定と違えば復元を確定しない。復元を確定した後も、復元通知とは別に端末内保存の完了表示を確認する。

### ⑥ 警告が出たら止める

起動失敗、保存失敗、保存停止、競合、保存結果未確認などが表示された場合は、次のように扱う。

- 登録・変更反映・復元の追加操作を止める。
- タブを閉じたり再読み込みしたりしない。
- データ削除・DB初期化・強制上書きをしない。
- 警告文を文章で記録する。
- 可能な場合だけ、登録済みの確定内容をJSONへ書き出し、取得を確認する。

保存停止中でも入力欄が使える場合がある。操作できることと、保存が再開したことを混同しない。

JSONへ含まれない未確定入力が残る場合も、タブを残して保護する。

## 6. 確認済み範囲と判定の限界

### AI側の隔離Chromium試験

登録・編集・複数馬の片方編集・編集キャンセル・確認画面から戻る操作について、それぞれ記録された限定シナリオの確認がある。

JSON往復は、完全な仮データ2件、v2 JSON、空の別Contextへの復元という1シナリオで34観点成功。UI書き出し、実ファイル取得、復元・保存、別ページ読み戻し、記録・editor・原文・採番、指定した手動空欄の保持を確認している。

過去の「確認画面から戻る34判定」とは別試験であり、判定数を合算しない。前提の登録を新規登録試験の追加合格にも数えない。

### 不整合JSON拒否

GitHub Actions実行ID `43292945311` について、ユーザーが転記した結果概要で15観点成功を確認した。

対象は、空の復元先に対する表示・editor不整合のv2 JSON1例。拒否・無変更・正常JSON再選択の確認画面までの限定合格である。

AIがActionsログを直接検査した結果でも、Safariでアプリを操作した結果でもない。0件での拒否を、既存登録馬がある場合の保持の証明にしない。

### ユーザーによるiPhone／Safari確認

正式入口の起動・指定2件の読み戻し、混在JSONのiPhone取得などの報告がある。

これらはユーザー報告による限定確認であり、AI自身の実機操作や、全editor・DB内部・保管JSON全文の独立検査とは区別する。

以上の結果を、保存機能全体の完成や、データが消失しない保証へ広げない。
