## 3. 現在の機能と保存

文章から候補作成、登録前の手動修正、一覧・詳細、原文・注意事項表示、新規登録馬の登録後編集、編集確認・反映・キャンセル、JSONバックアップ・復元を備える。

登録・変更反映だけではファイルに保存されない。データは画面内の一時保持で、再読み込みすると消える。保存にはJSON書き出しが必要。自動保存・永続保存は未実装。

## 4. 編集仕様（引き継ぎに基づく）

- 新形式の馬の詳細に「この馬を編集」を表示する。登録前の手動修正を引き継ぐ。原文からの再解析だけで編集状態を作らない。
- 編集用データと登録済みデータを分離する。「変更内容を確認」から「変更を反映」で対象だけ更新する。
- ID、番号、登録順、頭数を保持する。同名馬もIDで区別する。
- 空の馬名では確認に進めない。キャンセルは破棄確認後、元の記録を保持する。
- 登録後編集の原文は参照専用。項目修正で原文を書き換えない。
- 原文の不正値を手動修正した場合、注意事項を「原文履歴・手動修正済み」として区別して残す。
- 変更反映後はファイル未保存とバックアップの必要性を案内する。

## 5. JSON互換性

- 旧形式：kind=horse-app-backup、version=1。表示用情報、原文、注意事項等を保持するが、編集再開に必要な入力状態は保持しない。
- 新形式：kind=horse-app-backup、version=2。編集用データを追加保存する。
- 新アプリは両形式を読み込める設計。新形式JSONを旧アプリで読める保証はなく、画面にも旧版では読み込めない旨を表示する。
- 旧記録は一覧、詳細、再バックアップが可能だが、登録後編集は対象外。「この記録は旧形式のため編集できません。閲覧とバックアップはできます。」と表示する。原文からの推測変換や自動再登録はしない。
- 新旧混在JSONを保存・復元でき、復元後も新記録だけ編集可能。
- 新記録のeditorは主にs、f、dn、cmnを持つ。旧記録のeditorはnullとして扱う。これは引き継ぎ情報であり、変更前に実コードのキー・検証処理を再確認する。
